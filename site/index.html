Three things happen

Discodex never calls a provider API and never reads network traffic. Everything it knows comes from files already on the disk.

It reads the log your agent already writes.

One adapter per harness, for the shape it actually uses: append-only JSONL, rewritten JSON documents, Markdown transcripts, or SQLite.

It drops everything that is not on the list.

Events are reduced to six fields before a payload exists. Prompts, responses, paths, commands and tool output have no field to travel in.

It publishes over Discord IPC.

A thin client keeps the activity alive, reconnects when Discord restarts, and clears presence the moment you exit.

What it does with the rest

The parts that are not the privacy boundary: how a session is chosen, where the settings live, and what happens when Discord is not running.

Tools win over idle

When several sessions are open, one running a tool takes the slot. Otherwise the most recent wins. Window focus is ignored.

Four store shapes

Append-only logs are tailed. Rewritten documents are re-read. Databases are polled. Each harness uses the one it has.

Install

One executable, no installer, no account. It needs Windows 10 or 11 and Discord Desktop running for presence to appear.

  1. Download discodex.exe

    Grab the file from the latest release. Nothing is bundled around it.

  2. Run it

    The icon appears in the notification area and the config file is created on first launch.

  3. Leave Discord running

    Presence connects over IPC, and reconnects on its own if Discord starts later.

Build from source 
# Rust 1.85 or newer
git clone https://github.com/braces157/discodex.git
cd discodex
cargo test
cargo build --release

# your own Discord application ID
$env:DISCODEX_DISCORD_APPLICATION_ID = "YOUR_ID"
cargo build --release

in two minutes
